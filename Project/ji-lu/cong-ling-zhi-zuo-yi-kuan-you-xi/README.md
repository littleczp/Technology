## 游戏要素

{% hint style="info" %}
一款完整的游戏有哪些要素？

AI：核心玩法、内容与结构、叙事与世界观、美术与音效、系统功能

1. 核心玩法
   1. 核心循环：玩家反复做的那个动作是否有趣？
   2. 玩法深度：随着游戏推进，难度和机制的变化，让玩家不是从头到尾重复同一件事。
   3. 操作手感：输入反馈是否及时、准确，这在动作类游戏里尤为关键。
2. 内容与结构
   1. 关卡/流程设计：有明确的开始、发展、结局，节奏张弛有度。
   2. 难度曲线：循序渐进，不会突然卡关或过于简单。
   3. 游戏时长与内容量：跟价格和玩法类型相匹配，比如一个20元的小游戏拥有2小时的内容是合理的。
3. 叙事与世界观（非必须）
   1. 一致的世界观设定
   2. 角色的动机
   3. 叙事节奏与玩法的融合
4. 美术与音效
   1. 视觉风格：风格一致
   2. 音效与音乐：哪怕最简单的音效也会增加游戏的可玩性
   3. UI：菜单、按钮是否清晰易用，玩家生命值、技能冷却是否显眼
5. 系统功能
   1. 存档/读档：有无自动存档
   2. 设置菜单：音量、分辨率（全屏、窗口化）、按键绑定
   3. 本地化：支持单一或多语言
   4. 新手引导：是否支持跳过
{% endhint %}

## 游戏开发手册

在确认《游戏设计》大纲后，我们进行游戏制作前的最后一步，制定游戏开发手册（PRD）。

{% hint style="info" %}
一份完整的AI游戏开发手册应该包含哪些内容/结构？

一、设计层（Design Layer）

1. 游戏概述（类型、平台、核心体验锚点）
2. 非目标（明确砍掉、推迟或禁止实现的功能）
3. 核心循环
4. 术语表（统一核心系统命名、变量缩写、状态枚举）

二、协议层（Contract Layer）

1. 技术栈与环境基准（游戏引擎）
2. 目录结构与命名规范
3. 场景与资源契约（缺失资源时的占位机制）
4. 静态数据：数据表 Schema 与存档格式（Json/ScriptableObject/二进制及版本迁移）
5. 动态数据：事件总线与生命周期时序（全局 Event 定义、Update 执行优先级）
6. 模块边界与依赖方向（单向依赖规则、禁止的反模式/防循环依赖约定）

三、执行层（Execution Layer）

1. 任务切分与上下文管理（单次 Prompt 的任务粒度标准，避免超出上下文窗口）
2. 验证与调试规范（单元测试、可视化 Gizmos、作弊/调试指令要求）
3. 工作流与重构流程（读文档 -> 出技术方案 -> 编码 -> 人工/自动化复核）
4. AI 协作约定（System Prompt 片段、禁止输出未完成的代码伪代码片段、强制类型检查）
5. 架构决策记录（ADR）（记录重大设计变更及“为什么不采取另一种做法”）
{% endhint %}
