## 前置动作
先打开大纲的 [待游玩确认] 清单，逐条问我：现在这个原型能回答它了吗？
- 能回答 → 记进 ADR，从清单移除。

## 只写三份

### 1. AGENTS.md（≤ 60 行，硬上限）
一句话定位 / 文档地图 / ID 与命名规范 / 依赖方向铁律 / 红线 / DoD。
每一条必须对应仓库里真实存在的东西。写不出对应代码的条目，删掉。
不许写玩法内容。

### 2. 术语表
一词一义，标注归属系统，禁止同义词并存。只收录代码里已出现的词。

### 3. ADR
只记录已做出且改起来很贵的决定。每条 ≤ 5 行：背景 / 决定 / 放弃了什么。
"我们打算……"不是 ADR。
把大纲的非目标清单原样附在末尾,它是长期有效的否决依据。

## 不要写
- 尚未实现的系统的接口
- 事件总表（只收录已有 ≥2 个真实调用方的事件，写不满就空着）
- 目录结构说明（让 agent 看仓库，或在任务包里贴）
- 技术栈选型理由（已经选完了，ADR 一行即可）

## 自检（机械判定，不许主观回答）
- AGENTS.md 是否 ≤ 60 行？
- 每条规则，能否指出仓库里至少一个遵守它的文件？指不出就删。
- 术语表每个词，能否在代码里 grep 到？grep 不到就删。
- 三份加起来是否 ≤ 10 页？超了就减少内容。
